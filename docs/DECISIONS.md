# Design and security decisions

The decisions behind Bifrost 0.1.0, each with the reason for it. They are
settled: reopen one only with a clear new reason.

## Architecture

- **The system's `ssh`, `sftp`, `ssh-keygen` and `ssh-add`; no `russh`.**
  Bifrost stores and gives access to what ssh already does, so it reuses the
  user's OpenSSH setup (agent, known hosts, config) instead of reimplementing a
  protocol and its security surface.
- **No async runtime; a synchronous loop with crossterm and ratatui.** A TUI
  that waits for keys and spawns `ssh` has nothing to run concurrently, and
  `tokio` would add a large dependency tree for no benefit.
- **Library plus a thin binary.** `src/lib.rs` holds every module and
  `src/main.rs` only parses arguments and dispatches, so nearly everything is
  testable without spawning the program. `#![forbid(unsafe_code)]` applies to
  both.
- **One error type per module, wired into `AppError` when the CLI or TUI uses
  it.** Each module states its own failures without depending on the
  application layer.
- **Library code returns warnings; it never prints them.** The caller decides
  how to show them (stderr for the CLI, notices in the TUI), and tests can check
  them. UIs that add or edit a host must ask for the warnings themselves.
- **Environment access and the home directory are injected.** Tests stay
  hermetic without mutating the process environment, which is `unsafe` in
  edition 2024. Only the entry point passes the real environment.
- **No dead code or unused error variants, except defense-in-depth checks in
  security-critical paths.** Escaping and argument building keep real runtime
  checks in release builds, because a `debug_assert!` disappears where it
  matters.
- **Package `bifrost-ssh`, binary `bifrost`.** The plain name is taken; the
  command users type stays short.
- **Linux, macOS and Windows for 0.1.0.** Windows is tested in CI and in a
  separate VM.

## Store

- **A single TOML file owned by Bifrost, with `version = 1` and unknown fields
  rejected.** One readable, diffable file; a version to migrate from; and typos
  are errors instead of silently ignored settings.
- **Location: `$XDG_CONFIG_HOME/bifrost` (default `~/.config/bifrost`) on Linux,
  `~/Library/Application Support/bifrost` on macOS, `%APPDATA%\bifrost` on
  Windows.** Each platform's own convention. `BIFROST_CONFIG_DIR` overrides it
  and must be absolute, so the location never depends on the working directory.
- **One invalid host fails the whole load.** The error names the file, the host
  or line, and says to fix it or restore `hosts.toml.bak`. Loading a partial
  store would hide data and could lead to saving it away.
- **Saving refuses to overwrite a file that is invalid or newer.** Bifrost never
  destroys data it does not understand.
- **Atomic writes (temporary file plus rename) with a backup of the previous
  version.** A crash or full disk cannot leave a half-written store.
- **A host used as a jump host cannot be deleted; renaming rewrites
  references.** References can never dangle.

## Connections

- **The remote user is passed with `-l user`, never as `user@host`.** The
  destination stays a single validated hostname.
- **The destination comes after `--`.** Nothing in it can be read as an option.
- **Port forwards bind to localhost only; there is no bind address field.**
  A forward reachable from the network is an easy mistake and a serious one.
- **`ProxyJump` references another saved host, with chains of up to 5 hops and
  cycle detection.** Hops are expanded to `user@host:port`, outermost first.
  `ProxyCommand` and `LocalCommand` are never created: they run arbitrary
  commands.
- **`IdentitiesOnly=yes` whenever `identity_file` is set, on export and when
  connecting.** ssh offers only the chosen key instead of trying every key in
  the agent, which avoids "too many authentication failures".
- **No free-form ssh options field.** Every option Bifrost passes is one it has
  validated.

## Import and export

- **Import is a minimal scan of `Host` names (following `Include`, skipping
  wildcards), then `ssh -G` resolves each one.** ssh itself is the authority on
  its config semantics; Bifrost does not re-implement them.
- **Imported values go through the same validators; invalid hosts are skipped
  whole and reported; existing hosts are never overwritten.** Imported data is
  as untrusted as typed data.
- **The resolved user is always stored; port 22 is stored as unset; ssh's
  default identity files are dropped; the first explicit `IdentityFile` is kept
  (with a warning if there are several); `.pub` identity files and non-localhost,
  Unix-socket and dynamic forwards are dropped with a warning.** The store only
  holds what Bifrost can represent and connect with safely.
- **Export writes `~/.ssh/bifrost_config` with a "Generated by Bifrost" header,
  never edits `~/.ssh/config`, and refuses to replace a file without the
  header.** The user's own config is theirs; they add the `Include` line
  themselves. Notes, tags and favorites are never exported.
- **Exported values are quoted and escaped (`\`, `"`, `%`).** A value cannot
  inject a directive, even if validation were bypassed; the escaping keeps its
  own runtime check.

## Security

- **No secrets are stored.** Only paths to key files. Password authentication is
  left to ssh's own prompt.
- **Files are 0600 and directories 0700 on Unix, with a warning on load if
  broader.** Host lists reveal where a user connects.
- **Processes are spawned directly with an argument vector, never through a
  shell.** There is no shell to inject into.
- **Every field is validated:** values starting with `-`, newlines and control
  characters, surrounding whitespace and out-of-range ports are rejected. Notes
  are the exception (they may start with `-` and hold spaces, newlines and tabs)
  because they never reach ssh and are never exported; other control characters
  are still rejected.
- **Host key checking is never disabled.** A changed host key is shown as a
  possible attack, and removing the old entry needs explicit confirmation.
- **Key generation defaults to ed25519; passphrases are typed directly into
  `ssh-keygen` and `ssh-add` with the TUI suspended and never passed as
  arguments.** Arguments are visible to other processes.
- **Copying a key to a server sends only the public key, on stdin, to a fixed
  remote command.** Key content is never interpolated into a command string.
- **Agent forwarding is off by default, with a warning if exposed.** A forwarded
  agent can be used by anyone with control of the server.
- **The `ssh` binary is resolved to an absolute path at startup; empty and
  relative `PATH` entries are rejected.** Nothing in the current directory is
  ever run. On Windows, `%SystemRoot%\System32\OpenSSH\ssh.exe` is preferred.
- **Logging is off by default; logs never contain secrets and are user-only.**
- **Dependencies are minimal, each justified, and `Cargo.lock` is committed.**
  Every dependency is attack surface.

## Terminal interface

- **External text is sanitized wherever it is shown.** Control characters
  (C0, C1, DEL, ESC) and Unicode bidirectional controls (U+202A to U+202E,
  U+2066 to U+2069, U+200E, U+200F, U+061C) are replaced with a placeholder.
  Escape sequences can rewrite the screen and bidirectional controls can make
  text read differently than it is stored.
- **The placeholder is ASCII `?`.** It renders reliably on the Windows console
  and on basic terminals. When something was replaced, the footer says so, so
  the user knows the text is not what was stored.
- **The TUI sanitizes at render time, the CLI at print time, and library error
  messages escape the same set of characters.** One classification
  (`sanitize::is_unsafe_char`) is shared, so the three cannot drift apart. Error
  messages can quote file contents, so they are sanitized too.
- **The terminal is owned by a guard that restores it on drop, with a panic hook
  that restores it before the panic message is printed.** A crash must not leave
  the user's shell in raw mode or on the alternate screen, and the message must
  stay readable. The guard can suspend and resume so `ssh` can take the
  terminal.
- **State and rendering are separate.** Key handling changes a plain `App` value
  and rendering only reads it, so behavior is unit-tested without a terminal and
  screens are tested with ratatui's `TestBackend`.
- **The real binary is tested in a pseudo-terminal, on Unix only.** Unit tests
  cannot show that raw mode and the alternate screen are left again, that the
  cursor comes back, or that a resize is noticed. `tests/pty.rs` runs the
  binary in a pty and rebuilds the screen from its output. It uses `rustix`,
  which is already in the tree through crossterm, as a Unix-only dev-dependency;
  Windows never builds it and covers the same code with unit tests only.
- **Only key presses are handled.** Windows reports a press and a release for
  every key, which would otherwise act twice.
- **A store that fails to load does not stop the TUI.** It opens and explains
  the problem in plain English, because a user with a broken file needs the
  explanation most.
- **Minimum terminal size is 60x15, with a message below it.** It fits the host
  list, header and footer planned for the next block, and avoids a broken layout.
- **One theme from the terminal's 16 ANSI colors; `NO_COLOR` removes color.** It
  follows the user's palette and accessibility settings. Meaning is never
  carried by color alone: errors and warnings have text labels. crossterm also
  strips color when `NO_COLOR` is set, so the plain theme goes further and
  replaces gray text with dim text, which stays distinguishable without color.
- **`bifrost list` writes host names to stdout and everything else to stderr.**
  The output can be piped and parsed. The TUI needs an interactive terminal and
  says so when it does not have one.
- **ratatui is used with default features off, and crossterm only through
  `ratatui::crossterm`.** There is exactly one crossterm in the dependency tree,
  and no proc-macro or calendar dependencies.

## Host library

- **Search is fuzzy subsequence matching with scoring, written in the project.**
  It is about 150 lines and needs no dependency. Letters can be spread out; a
  prefix, a word start or consecutive letters score higher; a match in the name
  outranks one in the hostname, which outranks one in a tag. Nothing is searched
  that could not be seen: name, hostname and tags only, never the user or notes.
- **Matched letters are shown bold and underlined, the selected row in reverse
  video, and favorites with a `*`.** None of these needs color, so they survive
  `NO_COLOR` and any palette.
- **The selection is remembered by host name, not by row.** It follows its host
  when the order changes, for example after a favorite moves to the top.
- **Every change is applied to a copy, saved, and only then shown.** If saving
  fails, the screen still matches the file, and the error says why. A form that
  fails to save stays open with everything typed, so nothing is lost.
- **If the store cannot be loaded there is no host list, and adding, editing and
  deleting are switched off.** `Store::save` would refuse to overwrite the
  damaged file anyway; the screen explains the problem instead of pretending.
- **The form uses the store's own validators, and the whole collection is
  validated again on save.** A field can never accept what the store would
  refuse, and what one field cannot know (a name that is taken, a jump host that
  no longer exists) is caught and shown on the right field.
- **A field is checked when the focus leaves it, not while typing.** Errors do
  not flash at someone still typing, and an error goes away as soon as the field
  is edited. Surrounding whitespace is trimmed on single-line fields, since it is
  never meaningful and the store would refuse it.
- **The jump host is picked from a list of hosts that would be valid.** Each
  candidate is tried against the real validation (no loops, at most 5 hops, and
  not pushing a host that hops through this one over the limit), so the list can
  never offer a choice that saving then refuses.
- **Notes are edited on one line, with `\n`, `\t` and `\\` as escapes.** A
  multi-line note from the store survives editing unchanged; a real multi-line
  editor would be far more code for a field that is never sent anywhere. The
  field's help says how to insert a line break.
- **Ctrl+C in a form with unsaved changes asks first.** Pressing it again quits.
  A keystroke must not throw away typed work.
- **Deleting needs the host's name typed exactly, case included.** It is a
  destructive action with no undo, so it takes a deliberate act, not a `y`.
  A host that others jump through is refused before asking anything, using the
  Block 2 error that lists them, because typing the name would lead nowhere.
- **The ssh command exists in two forms that cannot be confused.** `SshArgs` is
  what is spawned: one element per argument, no quoting, options first, then
  `--` and the destination. `DisplayCommand` is text for a person, quoted for
  their shell, and cannot become arguments. Real ssh confirms why `--` matters:
  without it, `-oProxyCommand=evil` is read as an option.
- **The display string is quoted for the shell, and refuses what it cannot quote
  safely.** POSIX shells get single quotes, inside which nothing is special.
  Windows gets double quotes, but `%`, `!`, `$`, the backtick and a double quote
  are still interpreted inside them by cmd.exe or PowerShell, so a value holding
  one is not shown rather than shown unsafely. A comma, bracket or leading `@` is
  quoted there too, because PowerShell reads them as syntax.
- **Copying asks the terminal to copy with OSC 52; there is no clipboard
  library.** The clipboard belongs to the terminal, which is what makes it work
  over SSH, where this tool is used. The alternative, a library such as `arboard`,
  would add between 17 and 53 crates depending on features, and on Linux the
  clipboard is served by the process that set it, so its contents vanish when
  Bifrost exits (its own documentation says so); it also has no clipboard to talk
  to over SSH or without a display.
- **The command is always shown on screen, and the message says "copy
  requested", never "copied".** A terminal that does not support OSC 52 ignores
  it silently, some ask first or have it switched off, and tmux forwards it only
  when its `set-clipboard` option allows. Bifrost cannot know whether it worked,
  so the on-screen command is the part that always does. It is drawn across the
  full width with no side borders, so selecting it with the mouse copies the
  command and nothing else.
- **The clipboard request is write-only and refuses control characters.** Bifrost
  never asks the terminal for what is on the clipboard, and text with a line
  break or escape is not sent: what is copied is meant to be pasted into a shell.
- **The real binary is tested in a pseudo-terminal, and the real ssh in ignored
  tests.** Screens are tested with `TestBackend`; the raw-mode, cursor, resize,
  save-to-disk and clipboard behavior is only visible in a terminal, and whether
  ssh reads the arguments as meant is only visible to ssh (`ssh -G`, which needs
  no network), so that test is `#[ignore]` and run by hand.

## Known limitations in 0.1.0

- **Jump host keys.** Bifrost expands a jump host to `user@host:port` from its
  own store, so the jump host's `identity_file` is not used for that hop. Its key
  must be in `ssh-agent` or be one of ssh's default keys.
- **Windows file permissions are not verified.** Bifrost relies on the ACLs
  inherited from `%APPDATA%` and does not check them. Verification is deferred.
- **Copying cannot be confirmed.** OSC 52 is a request; support varies between
  terminals and multiplexers. The command is always on screen as the fallback.
- **On Windows, a command containing `%`, `!`, `$`, a backtick or a double quote
  cannot be shown.** Those characters are still interpreted inside double quotes,
  and showing them unquoted would be unsafe. Such values are rare (a key path
  with a `%` in it, for example).
- **Notes are edited on one line.** Line breaks and tabs are typed as `\n` and
  `\t`.

## Out of scope for 0.1.0

Snippets, live status, tmux/zellij integration, an SFTP browser, persistent
tunnels, `ProxyCommand`, and Windows ACL verification.
